# 物化间架构设计

版本：D1／2026-09-23／已确认（D1–D5）。范围见 [产品设计](product.md)，依赖和验收见 [界面计划](ui-plan.md)，事实与决策历史见 [工作记录](worklog.md)。以下为已确认目标约定；实际完成状态见工作记录。

## 当前实现与保留项

React／TypeScript／Vite 栈不变，hash 旧链接保留。原单应用及未提交全文工作的基线证据见 [工作记录](worklog.md)。应用现在位于 apps/reading、apps/learning，共享内容迁至 packages/content/src；legacy 保存旧精选与原有编辑分层，books 保存当前规范正文，history 保存历史引用及明确映射。来源快照仍为 public/texts/wikisource.json。

原导入器和离线转换保留；联网下载改为新增待审候选，不覆盖当前快照。正文按书从同站静态 JSON 加载，附 contentRelease 校验；选择 fetch 是因为浏览器验证复现了动态模块导入失败缓存导致重试无效。静态产物可重建，不引入服务。兼容、转换与教学检查合并到共享内容验证入口。

## 单仓双应用边界

采用 npm workspaces，沿用当前锁文件体系，不引入新的构建平台：

```text
apps/reading    中文导航、全文阅读、解读、回味、中文本地存档
apps/learning   英文导航、选课、单元、练习、学习本地存档
packages/content
  共享作品／版本／原文／来源；原始快照、派生层、身份映射、校验器
  中文编辑内容与学习内容各自分目录、入口，引用同一原文
packages/ui    基础控件、品牌变量、无业务策略的存档编解码与浏览器适配
scripts/       导入和离线校验
```

应用不能互相 import；content 不依赖 React、浏览器存储或应用；UI 不含阅读／教学业务。存档基础适配虽复用，两个应用的 key、迁移、记录操作与数据实例完全独立。正文呈现由各应用组合，不做 `isLearning` 分支巨型页面。翻译、练习、中文解读分别加载，不让中文站承担全套课程包。按书加载静态正文，先显示目录再载正文；转换词典仅在需要时加载。实现前的主包体积问题见工作记录，最终构建尺寸和剩余告警也在该处记录。

当前命令契约：`npm run build:reading`、`npm run build:learning` 各自产出 `dist/reading`、`dist/learning`；`npm run check:content` 校验共享及两站引用；根 `npm run build` 构建两站。保留根 `npm run dev` 指向中文站，另加学习开发命令；源码迁移不要求改公开 hash URL。

## 正式存储与事实源

Learning 的课程编辑事实源为 `content/learning/*.yaml`，一课一文件；`schemaVersion: 1` 定义文件格式，`order` 定义显示顺序，lesson.id／version 继续承载稳定身份。固定 sections.meaning／wordsToNotice／context 映射到原有 Aid kinds，引用、审核及权利信息逐项保留。规范原文与拼音仍使用既有共享内容层。

`lessons:generate` 先做 YAML 严格结构与引用校验，全部通过后以临时文件原子替换 `packages/content/src/learning-units.json`。该 JSON 是提交入仓的运行时派生产物，前端继续读取原契约；`lessons:check` 检测过期产物，开发启动和构建自动生成。开发中编辑 YAML 后运行生成命令触发 Vite 更新。YAML／Zod 只作开发依赖，不进入页面运行时。模板与新建命令见 README；没有增加数据库、内容服务或用户数据迁移。

仓库结构化内容适用于本项目：单作者增补、静态经典、无实时协作或账户需求。它就是正式方案，非等待数据库替代的临时层。原始来源快照不可变；规范化原文、校正和教学内容经编辑审核入仓；派生产物可重建且禁止手工当作事实源改写。Git 保存内容历史，发布产物须携带自身引用的历史版本，不能要求读者访问 Git 才能找回笔记。

用户数据在各站 origin 的本地存储中独立保存。本次继续使用 localStorage，纯文本的小规模收藏／笔记／进度暂不需要 IndexedDB；写入失败必须有出口，不能假设配额无限。音频、图片或大量尝试历史成为实际需求时再评估存储升级。浏览器清理、换浏览器或设备不会自动恢复；主域与子域不共享存档，不用跨域 iframe 搬数据。站点界面明确“此浏览器、此站点”，完整 JSON 由用户下载保管。

## 内容身份与层次

| 实体 | 身份与版本 | 关系及职责 |
| --- | --- | --- |
| Work／Edition | 固定 workId、editionId | 作品不等于电子版本；Wikisource 页面修订记在 SourceRevision |
| SourceRevision | 不变 sourceRevisionId，原 URL／oldid／贡献历史／获取信息／许可与处理说明 | 保存原始 wikitext；站点许可声明与条目核验事实分开，不把空纸本信息伪填成已校勘 |
| Division／Passage／Sentence | 分配后永不复用的 ID；排序、标题为可变字段；正文有 textVersion | 段落属于篇章，句为段落锚点；首次从已有 ID 冻结身份，以后绝不重新按序生成 |
| Text revision | passageId + textVersion，来源范围和校正说明 | 原始底文不覆盖；新修订建立新版本；需要时可查看旧版本 |
| Display layer | 原文版本 + 映射版本 + 原貌／简体／繁体 | 只是展示映射，不以简繁转换结果覆盖底文 |
| Pinyin layer | 原文版本 + tokenId／跨度、候选读音、人工覆盖、审核状态 | 与显示层共享原文锚点；读音审核独立于分词或生成成功 |
| Editorial | 独立 ID／版本／类型／语言／作者／状态／来源许可 | 中文词义、今译、思想、上下文；英文翻译、文化讲解、教学改写各用不同类型，不能互充 |
| Collection／Path | 稳定 ID、已选原文引用与次序 | 精选只引用，不抄一份可独立改写的正文；跨书主题是编辑关系 |
| LearningUnit／Exercise | 稳定 unitId、unitVersion、exerciseId | 级别、前置、目标、步骤、一个或多个原文版本引用；题目、答案和反馈独立于中文页面 |

所有外露引用使用 `passageId + textVersion`，学习同时携带单元版本；“最新版本”只作明确入口选择。顺序字段可以改，身份不能改。新 ID 可采用带实体前缀的随机标识；可读 slug 只做别名，不以内容哈希、序号或标题充当永久身份。

旧 `z1` 等精选和现有 `ws-…` ID 全部进入别名／历史引用表。旧精选来源未核实，不能直接认定与新全文逐字同源：先保留其历史文字及解读版本，人工核对等价关系后转成共享正文引用；不等价处明确保留 legacy 版本。历史快照是兼容档案，不再作为两站平行维护的另一份现行原文。

### 对齐与审核

跨度统一用原文 Unicode 码点的半开区间，并保存引用文字校验；不能混用 JS UTF-16 下标。分句、分词、拼音、简繁各有处理版本与原文锚点。转换存在一对多、多对一或异体字歧义时保存显式映射；编辑人员用词组覆盖及上下文校正。无法确定映射或读音时保留原字、隐藏对应拼音并解释缺失，禁止错位注音。原貌层始终可达。

`draft → reviewed → published` 记录审阅人／时间／针对的原文版本；撤回为 `withdrawn`，不抹历史。生成者和审阅者分别记录；AI 起稿只能是 draft。文本修订后依赖它的翻译、拼音、题目需失效复核，不能沿用旧 reviewed 标记。正文的转录检查、许可核对、文义审阅和教学审核是不同字段，不用单一“verified”混淆。

中文允许无解读正文，显示准确缺项；旧 draft 解读若展示必须标记，不进入已审核每日池。学习“可开始”要求该单元所需原文、英文、拼音及练习通过各自审核；未完成审核的新增候选使用本地预览；明确授权公开的版本另由发布清单记录，保留真实审核状态。自动拼音对未审核全库不默认开放。

## 更新与旧记录契约

| 变动 | 内容处理 | 链接／个人记录处理 |
| --- | --- | --- |
| 标题或顺序变化 | 保持实体 ID | 原链接不变，继续位置按锚点而非序号 |
| 正文纠字、换修订 | 保持语义实体 ID，创建 textVersion，保留旧快照 | 旧记录仍指原版本；显示“原文已更新”及对照，确认后可另关联新版 |
| 段落拆分 | 新建子段落 ID，旧 ID 保留；人工审核一对多范围映射 | 有精确选区可映射；整段笔记留在旧段并显示多个后继，不复制成多份笔记 |
| 段落合并 | 新合并段 ID，旧段均保留及各自范围 | 两条笔记不互相覆盖；可定位新范围并保留旧引用 |
| 删除／撤回 | tombstone、原因及可能后继；身份不复用 | 默认保留可合法保存的历史文字；需移除公开历史时仍保留用户存档快照和元数据，不暗删用户文本 |
| 无确定映射 | 标为 unresolved，禁止按相似度静默迁移 | 历史引用页可看／导出；让用户选择关联，不能过滤丢弃 |
| 单元文字小修 | 新单元版本并声明兼容前版完成，题目 ID 保持 | 保留完成及旧答案，提供更新提示 |
| 单元目标或练习实质变化 | 新版本声明需复习；重构目标时新 unitId | “旧版已完成”保留，新版未完成；不迁用旧答案冒充新答题 |

路由继续支持 `#/read/{oldId}/{clear|explain|reflect}?path=…`、旧主题和来源入口。别名在静态应用内解析，hash 不依赖服务器重定向；不确定的映射进入历史页而非首页或 404。来源页同时支持 `/sources` 和 `#/sources`。学习站使用自己的单元路由及稳定 stepId，不复用阅读 mode。

### 用户数据格式与保存

中文新存档为 `wuhua:reading:v2`，学习为 `wuhua:learning:v1`；外层包含 schemaVersion、app、contentRelease、exportedAt（导出时），记录内含稳定 recordId、更新时间、引用版本和可读快照。中文记录覆盖 saved、draft、bookmark、lastRead、bookLast、settings；学习覆盖单元／步骤、练习尝试、完成版本、可选笔记／收藏与 settings。学习尝试存单元与题目版本、答案及反馈版本，避免答案变化后误解释旧记录。保存最初和最近尝试摘要，不无限追加操作日志。

笔记输入短暂防抖写入，失焦／换页前冲刷；明确提交后更新 saved，保留未提交草稿；收藏、题目提交和完成立即写；位置按稳定锚点节流。每次写入捕获异常，只有成功才显示已保存。多标签页通过 storage 事件和存档修订检查发现外部改动，冲突时保留两份草稿供选择，不做无提示的整包覆盖。失败时保留内存副本，提供包括未落盘会话在内的导出；关闭标签前提示有未保存修改，但不承诺浏览器强退仍能保存。

旧 v1 迁移先读取原始串并备份，独立于当前内容表解析所有记录，绝不先调用现有会丢弃未知 ID 的 parseStore。校验后生成新存档、读回核对，成功前不切换，也不删旧 key。未知引用保留原 ID、全部个人文字和“原文待找回”；旧格式没有的原文／修订只有在历史清单可证实时补，不能编造。超长旧笔记也不静默截断。损坏 JSON 的原字节可下载，恢复失败不触发默认空存档写入。

实际用户数据迁移须在另行明确授权后随发布安排；本次实现仅开发迁移器并用隔离测试数据验收。发布前明确迁移触发、可回滚版本与旧 key 保留策略。旧程序回滚不能理解新格式时提示使用新版本导出，不把过时 v1 当作最新记录覆盖 v2。

### 备份与恢复

完整 JSON 是恢复格式，包含草稿、已保存笔记、收藏、位置、设置、进度、历史／失联记录及引用快照。Markdown 是阅读副本，按草稿／保存状态分区，不能冒称可恢复备份。备份不上传；首次有记录及较长时间未备份时给轻量提醒，无后台备份承诺。

恢复先验证 app、schema、结构与资源大小限制，在内存预览新增／重复／冲突／未知记录；不执行文件中的 HTML 或脚本。默认合并，按 recordId 去重，同 ID 不同内容保留两版本并让用户选择；未知版本保留原文件并提示不支持。替换须单独明确确认并先导出当前数据。写入后读回核验，失败保留原存档；空文件、跨站文件、损坏数据不能覆盖现有数据。恢复到另一个设备是用户导入行为，不叫同步。

## 作者操作与发布约定

作者在仓库完成：选定 Wikisource 页面与修订 → 保存原始快照及来源／贡献历史／许可信息 → 离线转换 → 检查正文边界、模板与实际样例 → 分配／保持身份并审阅变更映射 → 编写或 AI 起稿独立辅助 → 分别审阅文义、读音、英文和教学 → 标记可发布内容 → 两站验证 → 单独申请发布授权。未知模板仍报错，不以清空标记假装导入成功；新书可能需要一次转换适配，但新篇／单元不应复制页面代码。

来源集中页按作品／版本列固定修订、贡献历史、修改说明及许可；各原文／单元提供通往相应条目的短链接，分享图片保留必要署名与可见短出处，网页深链能到完整说明。延续当前 Wikisource 路线，不在本设计里重新给所有来源作法律结论。新增译文／录音／字体分别保存权利依据；中文站继续本机宋体栈；V2 学习站分发固定版本的霞鹜文楷 GB 屏幕阅读版 WOFF2 Unicode 分包，附 SIL OFL 1.1 和来源说明，英文 UI 使用系统字体。缺权利信息的新增素材不得以“构建成功”进入发布清单。

离线校验覆盖所有引用、ID 唯一性、版本／映射无环、原文和派生层对齐、必需来源字段、按审核状态生成的目录，以及学习可开始条件。内容状态留在内容元数据；技术检查结果留在 worklog，独立记录。对每个学习单元人工检查英文是否足以完成练习，不能只验证字符串非空。

同仓配置两个发布目标，构建根在仓库根，以便访问共享模块；目标各自选择构建命令和输出目录。修改单一应用只需选择该发布对象；共享内容／契约变化必须验证两站，即使仅发布一站。各发布包固定 contentRelease，各自包含所需历史，允许分批发布但不假设两站内容同时更新；跨站链接缺内容时友好返回目录。

现有 Vercel 的实际项目绑定、自动部署触发、域名规则本轮未访问控制台核实。实施时可准备配置，推送／合并前必须先核实是否触发部署并取得匹配授权；本轮不配置项目、DNS 或发布。回退以对应应用的已验证产物为单位，内容历史和用户数据版本兼容须先验证，禁止用回滚删除新存档。

## V2 视觉实现补充

共享 UI 新增静态 BrandMark、首页 HomeButterfly 和主题切换。Three.js 仅从首页组件动态导入，阅读与课内没有动画引擎依赖。轨迹为纯函数缓存；字体资源自托管在 public/fonts，按 Unicode 范围请求。田字格由当前展示字形派生，不修改底文，也不新增用户存储。

学习进度 Entry 新增可选 exerciseId，仍用原 wuhua:learning:v1 格式；老记录缺字段可读取，优先回到未答题，全部已答回最后反馈。不改变已有 first／last／count、completed 或 unitVersion；未知题目位置回到有效位置，原答案记录仍保留。导出／恢复包含该可选字段。具体呈现见 [V2 界面计划](ui-plan.md)，实施证据见 [工作记录](worklog.md)。

## V3 分享、打印与辅助材料契约

ShareCard 接收调用方的 passages（Reference、caption、可选公开 link），多段不默认选择。字符转换与字体就绪后，makeShareImage 根据测量结果产生 PNG Blob 和实际尺寸。预览和下载引用同一个对象，不另绘 HTML 或第二张图；生成 key 隔离异步结果，effect 清理释放 object URL。连续节选允许仅增加布局换行。英文卡使用学习字体及 Wuhua Learn，草稿无链接；组件拒绝在卡片写入非 HTTPS 或 localhost 地址。分享状态不写用户存档。
