# 订正清单起草说明（corrections13）

古文语料库 wuhua-corpus 攒了一批“只记未改”的底本问题，记在 /Users/congwang/Projects/wuhua/docs/corpus-issues.md。你负责其中一部或几部书：逐条回到原文和对校本核实，把确实该改的写成订正清单。宁可少改，不可错改；每一条都要有看得见的依据。

## 改什么，不改什么

改（页面上会直接显示成错误的）：
- 错字、衍字、脱字，且有对校本或本书内证支持。
- 残留符号：孤立的「《」、反斜杠、多余的「<」、占位的 ■ □ {…}、混入的假名或字母、校勘括号。
- 标点、引号：断句不通、引号缺失或多余、半角标点、多余或缺少的句读。
- 一句拆在两段：只有问题清单明说可以把半句挪到另一段、且两段都不会变空时才做（写成两条：一段删去半句，另一段补上）。

不改：
- 清单里写“异文”“两可”“不必改”“存疑”“待定”的条目；没把握的条目。
- 需要增删段落、合并段落、改分段、改章节标题的条目。标题行一律不动。
- 清单里“维基文库也错、本站对的地方”和“两边同误”的条目。
- 不要顺手把底本的异体字、通假字改成对校本的字；不要改清单没提到的地方，除非你在核实同一段时看到确凿的同类错误（那也要单列并写依据）。
- 清单里的条目若在现有原文里已经改好了，记为“已改”，不重复写。

## 怎么核实

工具（在 /Users/congwang/.cache/wuhua-annotate/c13/ 下运行）：
- `python3 tools.py para <书id> <段落id末四位> [章节标题片段]`：看一段原文。
- `python3 tools.py show <书id> <字串> [章节标题片段]`：找含这串字的段落。
- `python3 tools.py ws <对校本名> <字串>`：在对校本（ws/<名>.json，维基文库原始文本清洗后）里找这串字，默认忽略标点、繁简；加 `--raw` 按字面找（核对标点时用）。
- `python3 tools.py check <清单.json>`：检查清单格式，打印每条改动前后。

每一条都要做三件事：读我们这一段的现有原文；在对校本里找到对应的句子，确认对校本作什么；确认改后的句子读得通。对校本没有这一句、或对校本支持我们现有的字，就不改，记下原因。对校本只是一个本子，它也会错：字句讲不通时相信文义和本书内证（同篇他处的写法、同段的古注），并在依据里写明。

可以联网查维基文库、CBETA 等原始文本来补充依据（用中性的 User-Agent，如 `WuhuaCorpus/1.0 (personal classical text archive)`，请求间隔 3 秒以上），但不要凭记忆下结论。

## 输出

在 c13/ 下写两个文件（NAME 由任务指定）：

1. `NAME.json`：数组，每项 `{"book":"书id","id":"完整段落id","find":"…","replace":"…","reason":"…"}`。
   - `find` 必须是该段现有原文里一字不差的片段，在该段内只出现一次（不唯一就把前后文多带几个字）；`replace` 是改后的同一片段。片段尽量短，但要唯一。
   - 一条只改一处。字形跟着底本走：底本是简体就写简体，是繁体就写繁体；引号用本书自己的那一种。
   - `reason` 用一句中文写清改了什么、依据是什么，如“‘五恭’作‘王恭’，据维基文库《世說新語》德行第一及刘注”。
   - 写完运行 `python3 tools.py check NAME.json`，必须 bad 0。
2. `NAME.md`：问题清单里属于你的每一条各占一行：`采纳｜段落id末四位｜改动｜依据（引对校本原文十来个字）`，或 `不改｜段落｜原因`，或 `已改｜段落`。最后一行写总数：采纳几条、不改几条、已改几条。

不要改 c13/ 以外的任何文件，不要碰任何 git 仓库，不要运行会写入仓库的命令。完成后只回几行：采纳、不改、已改各几条，以及你认为需要人再看一眼的条目。
