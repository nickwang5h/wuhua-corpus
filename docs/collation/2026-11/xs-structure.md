# 《象山集》（lujiuyuanji）分章与四库本卷次对照

底本：殆知阁 daizhigev20 `象山集象山语录.txt`（四库本，commit 4a6d6f2）。对校：维基文库《象山集 (四庫全書本)》，缓存在 `c13/ws/象山集 (四庫全書本).json`（38 页）。脚本在 `c13/xs/`：`analyze.py`（找卷首、卷尾行）、`cover.py`（逐卷比对 6 字片段覆盖率）、`diff.py`、`table.py`、`makeops.py`（生成两档操作）、`dryrun.mts`（只读试跑 applyStructure 和主站 partition）、`refs.py`/`refs2.py`（主站引用）。

## 结论先说

- **不缺卷。**四库本全书共三十六卷：正集二十八卷、外集四卷、语录四卷，本库都有。另外卷首的提要、三篇序跋和完整目录也在。逐卷和维基文库比，6 字片段的双向覆盖率都在 0.91–0.98 之间，字数差不到 0.5%。只有三处例外，都不是本库缺文：
  - 维基文库的“卷09”一页里装着卷九、卷十两卷，它没有单独的卷10页。所以本库卷九、卷十合起来对维基卷09，覆盖率正常。
  - 卷十九《荆国王文公祠堂记》（0339）比维基四库本多 440 字。这是 corrections 据四部丛刊本补入的，主站版本说明已经写明。
  - 目录（ch3 0184–0187）在外集之后列有“策问对、文安谥议、覆谥、行状”四题，但维基四库本和本库正文都没有这四篇。这是四库本本身或抄本的问题，本库与四库本一致。
  - 所以“本站暂收部分卷次”这句话不对。
- **错的只是分章和章题。**底本切章时，把目录里的“卷一”“卷六”两行，以及卷八、卷二十、卷二十三三卷的卷尾题行“象山集卷X”，当成了下一章的章题。这五行因此从正文里消失，各章章题都与内容不符。五章正文（ch2–ch6）恰好在卷与卷之间断开，没有一章是从卷中间切开的。

卷首、卷尾行的情况：

- 每卷开头的“钦定四库全书”和“象山集巻X”两段都还在，共 36 卷。

## 3. 缺卷与并卷

- 不缺卷，见上。
- 并卷有四处，章题都取了别的行：
  - ch3 题“卷六”，实为目录后半加卷一至八。
  - ch4 题“卷八”，实为卷九至二十。
  - ch5 题“卷二十”，实为卷二十一至二十三。
  - ch6 题“卷二十三”，实为卷二十四至二十八、外集四卷、语录四卷。
- 目录也被拆在 ch1 末尾、ch2 和 ch3 开头三处。
- 主站上的效果：长章分页后，页题变成“卷八（一）”到“卷八（十一）”、“卷二十三（一）”到“卷二十三（十三）”这样，读者按卷次找文章必然找错。

## 4. 修正方案

两档都用 `dryrun.mts` 试跑过：读 `corpus/structure.json`，加入本书的操作；按 `scripts/structure.ts` 的路径走一遍（asSourced → applyStructure → 套回 corrections → digest 核对）；再用主站 `src/content/parts.ts` 的 `partition()` 分页。全程只读，两个仓库 `git status` 都是干净的。两档都通过 `validateBooks`，corrections 全部带过去，没有撤下任何段落。

## 5. 建议

建议做**档二**，理由如下：

- 本书其实是全本，各卷长度又正好一卷一页，拆开后得到的就是四库本原来的结构（目录 + 三十六卷），读者按卷次能直接找到。
- 档一只能让标题不再说错，“卷九至二十（七）”这样的页仍然要读者自己去猜卷次。
- 两档都要改主站约 44 处 `expect`；档二多出来的成本主要是重写导读和改页号，是一次性的。现在的导读里本来就有好几篇在解释“本页虽题卷二十，实为……”，拆章后这些解释都不需要了。
