# 物化间 · Wuhua

现代古籍句读阅读器 MVP。独立于 FateOS，默认运行在本机 4174 端口。

## 运行

需要 Node.js 22.12+。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:4174 。

```sh
npm test
npm run build
npm run preview
```

开发与预览共用端口，运行预览前先停止开发服务。可交付的静态资源位于 `dist/`，Vercel 项目使用 Vite 框架，并在每次构建前运行测试。

## 本版功能

- 《庄子》《道德经》《论语》各六则精选，支持按书筛选、检索原文和概念。
- 清读、解读、回味三种状态；字号调整、专注模式、方向键翻页和选段目录。
- 字词 → 句意 → 思想 → 上下文，逐层主动展开。
- 先写理解，再显示对照释义；本地草稿、保存、修改、删除与 Markdown 导出。
- 句子收藏、阅读位置恢复、概念关联和四条跨书共读路径。

## 内容与记录

现有选段保留原文字面和阅读顺序，底本、授权及人工校验状态均为待核验。中国哲学书电子化计划链接只作交叉参考，不是下载来源或复用授权凭证。现代释义为本版入门解读，仍处于编辑草稿状态，不是历史注家引文；概念关联是编辑对读，不是学术等同关系。

### 模块化内容试行版

内容位于 `src/content/`，暂不拆独立仓库，避免引入发布、同步和依赖管理负担：

- `works.ts` → `editions.ts` → `divisions.ts` → `texts.ts`：作品、版本、篇章、段落及句子。三本书分别用 essay/chapter/sayings 表达篇、章和语录结构；本次仍为选段，不代表全本。
- `annotations.ts`：独立挂接段落 ID 的字词、今译、解读、反思、概念及展示分行。当前每段只有一份编辑注解，不提前实现多注家选择。
- `sources.ts`：底本、修订号、权利证据、处理与人工核验状态。未知字段为 null，不把古代作品公版推断成电子版本已授权。
- `concepts.ts`、`paths.ts`：概念关系与阅读路径，独立于原典。
- `catalog.ts`：组合并校验 ID、引用关系、分行一致性与来源证据；失败时阻止构建/运行，不静默丢弃内容。
- `src/content.ts`：兼容现有阅读器的投影。原有 z1/d1/l1 等 ID 保持不变，因此笔记、收藏和链接无需迁移。换底本时应新增版本和段落 ID，不覆盖已有引用。

原有选段暂各存为一个句子单元；显示换行不是经过校勘的句界。后续细分句子时需保留段落 ID，并显式管理句子 ID。

`wikisource.ts` 提供纯函数 `stageWikisource(snapshot)`：输入页面 URL、明确 revision、底本、权利证据及已提取的正文段落，输出带 oldid 的来源和候选文本，不联网、不写入现有目录、不自动宣称公版。先核验具体页面/版本的许可，再提取正文（排除导航和现代评论），补齐 edition/division、独立注解并人工校对，最后接入 catalog。不得用随意填写的修订号或许可证替代核验。尚未实现在线抓取、全本导入或 Harvard/Kanripo 接入。

在项目根目录执行 `npm test` 和 `npm run build` 验证内容关系与阅读器兼容性。存储校验、阅读顺序与导出逻辑在 `src/model.ts`。路由使用 URL hash，刷新和直接打开选段均可用，无需服务器路由配置。

记录只存在当前浏览器的 `wuhua:reading:v1`，不上传，不调用 AI 或第三方服务。清理浏览器数据会丢失记录，请通过“我的回味”导出。导出包含已保存理解，不包含尚未提交的草稿。

本版不含全本古籍、历代注家对读、实时 AI、账户或云同步。
